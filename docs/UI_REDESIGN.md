# PRISM UI redesign

The redesign keeps PRISM's violet/lavender/ink tokens, logo assets, Indonesian terminology, system sans typography, and restrained surfaces. Tailwind 4.2.1, its CSS-first theme and source configuration, and the existing local asset build remain unchanged.

## Page composition

- Public home: a clearer introduction and three linked steps for discovery, availability, and submission.
- Workspace: labelled navigation with icons, persistent role/account context, responsive drawer, and consistent cards, controls, tables, badges, and feedback.
- Facilities: collapsible mobile filters, immediate search within server results, image-led cards, gallery/facts overview, and labelled availability states.
- Reservations: three grouped form sections, persistent desktop guidance, status-filtered history, and a separate next-action/cancellation panel on detail pages.
- Reports: one shared field fragment for full-page and HTMX dialog submission, searchable status history, and separate evidence and handling panels.
- Operations: dashboard section shortcuts, searchable queues, compact blockage records, and expandable early-completion forms. Existing impact preview and confirmation remain required.
- Administration: searchable management lists, separate type-creation panels, visual occupancy meters with numeric values, and grouped application settings.
- Account/authentication: shared account tabs, profile/security columns, a reusable branded authentication panel, full-width sign-in actions, and optional password visibility controls.

## Contracts and accessibility

Routes, controller/model contracts, `th:field` bindings, upload names/encoding, CSRF, authorization expressions, validation, proposal rules, cancellation cutoffs, and cascade confirmations are preserved. The report page now has a normal standalone form; quick actions still load the shared dialog.

Search/status tools, password visibility, and character counts are progressive enhancements. Native forms, server filters, details/summary controls, validation errors, and records remain available without JavaScript. Existing focus handling, mobile drawer inertness, request guards, and reduced-motion support are retained. Avatar failures receive the existing placeholder.

## Verification

- `npm run build` compiles Tailwind and copies the existing HTMX vendor asset.
- `node --check src/main/resources/static/js/app.js` checks interaction script syntax.
- `python scripts/check-template-structure.py` checks balanced template markup and duplicate attributes.
- `mvnw.cmd test` runs the repository's unit and MVC/integration tests.
- `mvnw.cmd -Dtest=UiRenderingIntegrationTest -Dprism.ui.snapshots=true test` generates real Thymeleaf output with representative test data under `target/ui-preview`.
- `python scripts/ui-preview.py` serves those snapshots and production frontend assets at `http://127.0.0.1:8765/landing.html` for browser inspection. The preview is read-only and does not emulate backend requests; use the running application for end-to-end submissions.

The rendering tests cover role-specific navigation, forms, CSRF, HTMX regions, empty states, validation, reports, account settings, and administrative pages. MySQL concurrency integration tests remain a separate existing `mysql-it` profile.

### Results (11 October 2026)

- Final Maven run: 335 tests across 41 suites, zero failures/errors/skips. The rendering suite includes 20 checks.
- Tailwind build, all three changed JavaScript syntax checks, template structure validation, and `git diff --check` passed. Compiled CSS contains the checked shared components and interaction utilities.
- Browser QA: 18 representative views at 320/768/1024/1440 px, plus six report/account views at 320/768/1440 px, with no document overflow, duplicate IDs, or unlabeled text fields. Checked mobile filter collapse, search/empty feedback, history status filters, password visibility, and drawer state.
- Screenshots use real Thymeleaf output generated by MockMvc, with synthetic test data and production assets. Browser submissions against a live database and the separate MySQL concurrency profile were not run.
